## 2. 决策记录（为什么这么做，改主意先读这里）

- **为什么"离线优先"**：前几轮地图问题根因 = 依赖在线瓦片（OSM 国内慢 → 高德仍要网），断网即空白。Organic Maps 调研结论：数据/渲染都应在本地（见调研报告 §一/§三）。
- **为什么不整库移植 OM**：C++ 核心 15 万行、APK 40~85MB、.mwm 无公开文档、禁止白标——对个人玩具过重（调研报告 §三-A/B）。
- **为什么 P0 用瓦片缓存而不是直接矢量底图**：成本最低（1~2 天）、零新依赖、立即消除"断网没地图"；矢量底图（P2）是其自然升级。
- **瓦片源**：高德（国内 CDN 秒开）为主、OSM 兜底；坐标已做 WGS-84→GCJ-02 转换（既有实现，勿动）。

## 3. P0 瓦片预缓存（进行中）

### 3.1 目标与验收

- 目标：以 Home 为中心约 2.2km 范围（z13~z16，约 170 张瓦片、约 3.5MB）预下载到本地；断网/飞行模式下地图照常显示。
- 验收（逐条）：
  1. 开始拜年（Home 确定）后自动预载；也可点地图卡「预载周边地图」手动触发；
  2. 提示语显示预载进度与张数；
  3. **飞行模式**下重启 App → 打开记录页 → 村周边地图完整显示；
  4. 缓存总量有上限（64MB，LRU 淘汰最旧）；
  5. 网页版同构：SW 缓存高德/OSM 瓦片 + 预载消息通道 + 手动「预载」按钮；
  6. 两端新增测试全绿、CI 全绿。

### 3.2 安卓实现（进行中）

| 文件 | 职责 |
|---|---|
| android/app/.../TileMath.kt | Web Mercator 瓦片数学：lat/lng↔(x,y,z)、bbox→瓦片列表、高德瓦片 URL 模板 |
| android/app/.../TileCache.kt | 磁盘缓存：key=规范化 URL（去子域）、原子写入、LRU 按字节淘汰、HttpURLConnection 下载 |

| android/app/src/test/.../TileMathTest.kt | 瓦片数学单测（对照网页版 tests/tiles.test.ts 同一组已知值） |

### 3.3 网页版实现（进行中）

| 文件 | 职责 |
|---|---|
| src/tiles.ts | 瓦片数学 + URL 规范化（与安卓同一套公式） |
| public/sw.js | 瓦片缓存域名扩展到 *.is.autonavi.com + openstreetmap.fr；容量 600→4000；缓存 key 规范化（去子域）；新增 preload 消息通道；CACHE 版本递增 |

### 3.4 关键设计决策

- **缓存 key 规范化**：把 webrd0{1-4}/webst0{1-4} 子域归一（去掉数字），预载与运行时请求共享同一条缓存——否则子域不同会缓存未命中。
- **网络优先、缓存兜底**：安卓由 shouldInterceptRequest 统一代理瓦片请求（下载成功→写缓存→返回；失败→读缓存；无缓存→透传）；网页版 SW 对瓦片 cache-first（瓦片内容不可变）。
- **预载范围**：Home ±0.02°（约 2.2km）→ z13~z16（约 170 张/3.5MB；z16 街道级足以辨认村巷；z17 建筑级暂不预载，在线浏览顺带入库）。

### 3.5 风险与回滚

- 风险：高德瓦片服务条款对批量下载的限制（个人使用规模无虞）；预载约 4MB/次流量。
- 回滚：删除 TileCache/TileMath 与 shouldInterceptRequest 段即可，地图退回 WebView 自带缓存行为；SW 改动回退 CACHE 版本即可。

## 4. 后续阶段（未开始，启动前先读本节 + 调研报告对应章节）

### 4.1 P1 定位省电调度
- 参考：OM LocationHelper（android/app/src/main/java/app/organicmaps/location/LocationHelper.java）：移动 100ms / 静止 3000ms 动态切换 + 劣质点过滤。
- 做法：SystemLocationSource 增加速度/位移检测，静止时把 requestLocationUpdates 间隔从 1000ms 放宽到 3000ms；恢复移动自动切回。
- 验收：静止 1 分钟后定位请求量明显下降；移动后 1s 内恢复采样。

### 4.2 P2 离线矢量底图（选做，用户确认后启动）
- 参考：调研报告 §三-C2；OM 的县级切图流程（GeoJSON 边界 + osmium extract + Geofabrik pbf）。
- 做法：MapLibre GL Native + 昌乐县 PMTiles 自生成（≈2~20MB）；卫星层继续高德+缓存。
- 验收：飞行模式全功能（底图+轨迹+标记）；APK 增量 <15MB。

### 4.3 P3 断点续传下载器
- 参考：OM libs/platform/http_client.cpp（SetRange "bytes="、校验 206/Content-Range）与 storage/http_map_files_downloader.cpp（.downloading/.resume 保进度）。
- 做法：为 P2 离线包更新提供续传能力。
- 验收：下载中断后重试，进度从断点继续。

### 4.4 P4 A 档书面评估
- 内容：官方 SDK（app.organicmaps.sdk，Maven Central）依赖可行性 vs P2 方案的四维对比（体积/耗时/合规/维护）。
- 验收：报告成文并入库（docs/）。
