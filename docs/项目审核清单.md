# 拜拜 · 项目审核清单（验收审计标准）

> 本清单是「拜拜」项目（Web PWA + 安卓 App）的**专用审核文档**。适用时机：每个里程碑收尾、每次真机安装后、每次大改 UI/逻辑后、上线前。
> 使用方式：逐节核对，每项只允许回答 **是否通过**，禁止打分、禁止"基本没问题"。任何一项不通过，必须按 §12 输出：问题描述 → 严重程度 → 修复建议 → **直接完成修复** → 二轮复检。
> 挑错思维：审核者以 QA 身份工作，目标是找出问题，不是证明代码正确。

## 十、Bug 猎杀（最重要 · 以 QA 身份，主动找 Bug）

按下列场景逐一实测（能真机的真机，不能的至少 Robolectric/推理并记录）：

- [ ] **极快连点**：开始→暂停→继续→撤销 1 秒内狂点，状态机是否错乱、是否崩溃
- [ ] **极慢操作**：某户停留 20 分钟后再按继续（D22 用户最担心的场景）
- [ ] **进程被杀**：记录中从最近任务划掉 App → 重启 → 检查点弹窗 → 继续，计时/轨迹是否连贯
- [ ] **检查点损坏**：手工写入半截 JSON 后启动，是否优雅降级而非白屏
- [ ] **跨午夜**：23:59 开始拜年，0 点后结束，日期/年份归属是否正确

## 十一、安全检查

- [ ] JSON 导入是否有注入风险（Web：绝不 innerHTML 拼用户数据；安卓：JsonStore 解析失败是否安全返回）
- [ ] Web 是否存在任何 innerHTML 使用点（含动态生成 SVG/HTML 处）
- [ ] 文件导出路径是否安全（安卓 FileProvider 是否限定目录；导出文件名是否可被路径穿越）
- [ ] 高德 Key：是否只出现在本地/构建配置，**绝不提交明文到仓库**（`高德接入指引.md` 是否写明 SHA1/包名绑定）
- [ ] 权限是否最小化：仅定位 + 通知；无存储/通讯录等无关权限
- [ ] 隐私：轨迹数据全本地，无任何上传/埋点/第三方统计；SW 是否只缓存自家资源
- [ ] 依赖供应链：web 零运行时依赖、安卓依赖是否锁定版本（BOM/catalog）；无远程字体/图片/CDN
- [ ] 是否有无效链接/404 资源（含 SW 缓存清单与实际产物是否一致）

## 十二、最终输出要求（每次审核结束必须按此格式产出）

1. **已通过的检查项**：逐节列出（`§1 D0 通过；§4 记录页五项通过…`）；
2. **发现的所有问题**：每项给出——问题描述、复现步骤、涉及文件/页面；
3. **严重程度**：每项标注 `Critical`（数据丢失/功能不可用/硬性红线违反）/ `High`（主要流程受阻）/ `Medium`（次要功能或部分机型）/ `Low`（观感/文档）；
4. **修复建议**：具体到文件与改法；
5. **直接完成修复**：修复不是建议——审核者直接改完并重新验证；
6. **第二轮检查**：修复后重跑本清单，直到所有 Critical/High 清零、Medium/Low 明确记录为"已知可接受"或已修复。

**纪律**：
- 禁止输出"没有问题""基本通过"这类结论——每节必须给出逐项结论或明确证据；
- 严重程度判定先问一句"丢数据吗？红线违反吗？"——是即为 Critical；
- 所有修复必须过 CI（web 测试 / Android CI）+ 真机复核（涉及 UI 的必须）；
- 本清单本身也随项目演进维护：新增需求、新增页面时同步增补检查项。
