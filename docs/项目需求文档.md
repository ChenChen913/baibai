# baibai项目 · 需求与设计文档（grill 达成版）

> 本文档由 17 轮连环拷问达成共识后整合而成，与《拷问决策记录.md》一一对应（D0~D21）。
> 状态：设计已定稿，代码进度 0。

## 0. 一句话

乡村拜年轨迹复盘玩具：大年初一走村串户时用手机记录真实行走轨迹，用「暂停/继续」标记逗留的每一户；拜完年后回放当日路线，用路径规划算法算出**当日最优走法**与**飞行直线最优**，三线动画对比——看看自己今年绕了多少路。年度独立、每年一局、纯本地、自己玩。

## 1. 用户与场景

- **唯一用户**：作者自己（个人兴趣项目，不商业化、不做多用户）。
- **主场景**：大年初一全天（约 3~6 小时），步行为主、偶尔回家取车骑行；走访 10~20 户。
- **使用节拍**：
  - **出门前**（前一晚或早上）：可选"生成今年清单"（导入去年名单，可增删）。
  - **拜年中**：只做两件事——到一户按「暂停」，离开按「继续」；骑车段出门前点一下小车图标。
  - **拜年后**（回家，坐在屋里）：回顾页完成命名/套名、漏访检查、看三线动画与成绩单。

## 2. 产品形态与技术栈

| 项 | 决策 |
|---|---|
| 形态 | 网页版 PWA（纯前端、零后端），GitHub Pages 部署，可添加到手机桌面 |
| 地图 | Leaflet + OSM 瓦片（在线增强；村庄瓦片稀薄不致命） |
| 核心绘制 | 自绘 SVG/Canvas 节点-连线示意图（主展示，离线可用） |
| 定位 | 浏览器 Geolocation API（手机自带 GPS/北斗；户间距 200~500m，精度冗余 20~50 倍；**无需 RTK/外接设备**） |
| 存储 | IndexedDB 本地三张表；导出/导入单个 JSON 全量备份（换手机用） |
| 离线 | Service Worker 全量缓存，断网可跑 |
| 算法 | 纯 JS：轨迹平滑（卡尔曼/滑动平均）+ Douglas-Peucker 抽稀 + Dijkstra/Floyd + Held-Karp（n≤20 精确解 TSP） |
| 视觉 | 现代 CSS（浅色玻璃拟态）+ SVG/CSS 动画 |

**核心约束**：记录轨迹时手机保持亮屏（Wake Lock API；iPhone 需在设置里把自动锁定设为"永不"）；无后端、无账号、无云同步。

## 3. 数据模型（IndexedDB 三张表）

| 表 | 内容 |
|---|---|
| **nodes**（户） | id、名字（自由文本/数字/字母组合）、坐标、拜访顺序号、到达/离开时刻、出行方式（该段）、是否漏访标记 |
| **tracks**（路） | 当年原始轨迹点、平滑后轨迹、分段边（哪户→哪户、距离、耗时、步行/骑行） |
| **sessions**（场次） | 年份、日期、起点 Home、节点序列、多段循环结构、成绩单快照 |

**关键规则**：
- **节点合并阈值 10m**：新暂停点与已有节点 ≤10m 合并（含 Home 起止偏差），>10m 为新节点；回顾页手动合并/拆分/纠错为必备功能。
- **年度独立**：往年数据不参与当年优化；跨年不自动匹配；当年节点重新自动编号（1、2、3…按拜访顺序）。
- **可选跨年便利（都需人工确认，不点即无关）**：
  1. 出门前"生成今年清单"：导入去年名单（可增删）；
  2. 回顾页"套用去年的户名"：按距离推候选（最近 3 户），逐个确认或跳过。
- **中途回家**：允许多段循环；最优对比永远按单环（Home→全部农户各一次→Home）计算。
- **出行方式**：默认走路；骑车段离开前点小车图标，到下一户自动回走路。

## 4. 功能清单

### 4.1 出门前（可选）
- F-1 生成今年清单：导入去年名单 → 可增删 → 存为今年计划。

### 4.2 拜年中（核心交互：只需按两个键）
- F-2 开始/结束：Home 出发开始记录，回到 Home 结束；起点=终点=Home（≤10m 合并）。
- F-3 暂停/继续：到达一户按暂停（自动编号该户）；离开按继续。
- F-4 骑车标记：离开前点小车图标切换（默认走路，到下一户自动复位）。
- F-5 撤销：录音页撤销上一暂停点（误触补救）。
- F-6 反馈：开始/结束/到达暂停时震动+轻音效（可关）。
- F-7 实时浮窗：暖色玻璃胶囊，显示记录中状态与节点计数（不抢焦点）。

### 4.3 拜年后（回顾页，高潮所在）
- F-8 命名/套名：逐节点命名（自由文本）；或一键套用去年户名（逐个确认）。
- F-9 漏访检查：计划清单 vs 实际节点自动对比，漏访标红"XX 没去！"。
- F-10 数据收拾：合并/拆分节点、剔除异常样本（如中途聊天 15 分钟）、删除误录点。
- F-11 轨迹回放：运动 APP 式，沿轨迹行进光点 + 逐段点亮；速度 1x/2x/4x。
- F-12 三线优化：① 飞行最优（直线距离，精确）；② 当日时间最优（主展示，未走过边用速度折算）；③ 当日距离最优（未走过边=直线×绕行系数估算）。同一 Held-Karp 求解器三次换权重；估算边在图上明确标注。
- F-13 压轴 morph 动画：真实轨迹收缩 → 节点浮起 → 金色航线亮起（约 3 秒）。
- F-14 成绩单卡片：实走/当日最优/飞行最优三列对比 + 节省率 + 步行/骑行里程分解 + 拜访户数 + 漏访红标。
- F-15 历年成绩单列表（纯展示）：每年一张卡 + 绕路率趋势线（不混数据）。

## 5. 算法规格

- **输入**：当年节点集（含 Home）+ 当年真实分段边（距离=平滑轨迹长；耗时=离开时间戳差）。
- **三条最优线**：
  | 线 | 权重 | 未走过边的处理 |
  |---|---|---|
  | 飞行最优 | 直线距离 | 永远可算，**精确** |
  | 时间最优 | 真实耗时（同边多次取最短） | 距离 ÷ 步行 4.5km/h 或骑行 14km/h 折算，标"估算" |
  | 距离最优 | 平滑轨迹长度 | 直线 × 1.2~1.4 绕行系数，标"估算" |
- **求解器**：Held-Karp 动态规划（固定起点 Home，n≤20 精确最优）。
- **平滑**：卡尔曼/滑动平均去抖 + Douglas-Peucker 抽稀（轨迹更顺滑，但只画真实走过的路，不"拉直"造假路）。
- **异常样本**：比同边样本中位数慢 2 倍以上自动标异常，人工可剔除。

## 6. 视觉设计（D21 定稿）

- **基调**：大白天的暖色年味——浅暖色底（米白/淡金）+ 红色系柔和渐变，明亮优雅，**不做暗色/黑夜模式**。
- **装饰**：边缘点缀虚化、低透明的**礼花+炮仗**（只用这两样，不摆主体；春联不用）。
- **步行场景**：暖底 + 朱红轨迹线 + 发光节点 + 底部玻璃胶囊。
- **飞行压轴**：晴空感 + 鎏金节点（如灯笼）+ 金红航线 + 轻烟花粒子。
- **成绩单**：浅色玻璃拟态卡片，红色系数字强调。

## 7. 异常与兜底

| 情形 | 处理 |
|---|---|
| 锁屏冻结 GPS | 记录时保持亮屏（PWA 已接受该代价）；iOS/安卓差异实现时实测 |
| 进屋丢星 | 与"暂停"天然兼容；出门 3~10s 重新锁星 |
| 误触暂停 | 录音页撤销 + 回顾页合并/拆分 |
| 跨年定位漂移 | 无需处理（年度独立）；套名/清单继承均为人工确认 |
| 断网 | Service Worker 离线全量可用；OSM 瓦片缺失时切换自绘示意图 |
| 注入失败 | 不适用（无文本注入） |
| 换手机 | 导出 JSON 导入即可 |

### 长时间运行可靠性（D22 · 用户追加要求）

2 小时+ 的拜年会话不允许卡死；**即使卡死，也不丢数据**。六条硬性要求：

1. **Web Worker 隔离计算**：平滑/抽稀/Held-Karp/morph 动画预处理全部放 Worker，主线程只做 UI——杜绝计算型冻结；
2. **批量落盘**：GPS 点内存缓冲，每 5~10s 或每次按键时批量写 IndexedDB，绝不逐点写库；
3. **会话检查点（最重要）**：每 10s 或每次按键，持久化完整会话状态；异常退出后重开应用弹"检测到未完成的记录——继续 / 放弃"；
4. **亮屏保障**：Wake Lock API（Android/Chrome 原生）；iPhone 在部署文档注明手动设"自动锁定=永不"；
5. **错误边界**：全局未捕获异常 → 写日志 + 弹提示，绝不静默冻结；
6. **零内存压力**：不录音频，2 小时 GPS 约 7200 个点、几十 KB。

**设计要点**：暂停期间（在某户停留）停掉 GPS 监听与所有计算，只保留轻量待机界面——这是全程最安全的状态；恢复时重新获取定位（户外 3~10s），期间显示"正在定位…"，头几秒无轨迹点（人在屋内未移动，无影响）。

## 8. 非目标（明确不做）

- 不商业化、不做多用户、无账号云同步；
- 不做"明年路线规划"（需要历史累积，与年度独立矛盾）；
- 不做 RTK/高精度差分定位（户间距 200~500m，手机 GPS 已足够）；
- 不做小程序/原生 APP（网页 PWA 已定）；
- 不做实时逐字转写、语音指令、翻译等输入法类功能。
