# Android 迁移 · 防杀与后台定位指南（v1）

> 目的：实现"**锁屏揣兜里持续记录 + 进程不被杀 + 杀了也不前功尽弃**"。
> 结论先行：**没有任何魔法能 100% 保证国产 ROM 不杀后台**——正确策略是"四层防线 + 检查点兜底"，让"被杀"从灾难降级为无感事件。

## 0. 定位源选择（重要修正）

**用高德定位 SDK，不用谷歌 FusedLocation。**
国行安卓普遍无 Google Play Services，`FusedLocationProviderClient` 不可用或降级。高德定位 SDK：
- 融合 GPS + 北斗 + 基站 + WiFi，锁屏持续定位是官方支持场景；
- 与高德地图 SDK 一体化（一个 Key）；
- 个人开发者免费，Key 与包名/SHA1 绑定。

## 1. 第一层防线：前台服务 + 常驻通知（系统级保护）

**Manifest 声明：**

```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

<service
    android:name=".LocationService"
    android:exported="false"
    android:foregroundServiceType="location" />
```

**服务骨架（Kotlin 要点）：**

```kotlin
class LocationService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        startForeground(NOTIF_ID, buildNotification())   // 必须在 5s 内调用
        startLocationUpdates()
        return START_STICKY    // 第二层：被回收后系统自动重建
    }

    override fun onDestroy() {
        super.onDestroy()
        // 不做重型清理——START_STICKY 会带 null intent 重启，
        // 此时从检查点恢复状态继续定位
    }

    private fun buildNotification(): Notification {
        // 渠道："拜年记录中"；ongoing=true（不可滑动删除）
        // 文案动态：🎙 记录中 · 已拜访 N 户 / 🏠 在某户
    }
}
```

- **通知渠道**（Android 8+）：`NotificationChannel("baibai_recording", "拜年记录", IMPORTANCE_LOW)`；
- **运行时权限**：定位（`ACCESS_FINE_LOCATION`）+ 通知（Android 13+ `POST_NOTIFICATIONS`）双请求，拒绝时给出明确引导文案（对照网页版"定位错误可见化"的教训）。

## 2. 第二层防线：START_STICKY 自重启

- `START_STICKY`：系统内存压力回收后，**带 null intent 自动重启服务**；
- 重启后：读取最新检查点 → 恢复 `RecorderState` → 继续定位 → 通知恢复；
- 重启逻辑做成纯函数 `resumeFromCheckpoint()`，与冷启动恢复共用同一段代码。

## 3. 第三层防线：省电白名单引导（国产 ROM 决定性动作）

首次启动/首次开始拜年时，**图文引导**用户完成对应设置。路径矩阵（以 2026 年常见 ROM 为准，实现时逐台核对）：

| ROM | 设置路径 |
|---|---|
| 小米/红米 (MIUI/HyperOS) | 设置 → 应用设置 → 拜拜 → 省电策略 → **无限制**；并开启"自启动" |
| 华为/荣耀 (EMUI/HarmonyOS) | 设置 → 应用 → 应用启动管理 → 拜拜 → 手动管理 → 允许**自启动/关联启动/后台活动** |
| OPPO/一加 (ColorOS) | 设置 → 电池 → 更多设置 → 拜拜 → 允许**后台运行**；应用管理里开自启动 |
| vivo/iqoo (OriginOS) | i管家 → 电池 → 后台耗电管理 → 拜拜 → **允许后台高耗电**；权限里开自启动 |
| 三星 (OneUI) | 设置 → 电池 → 后台使用限制 → 拜拜 → **不休眠** |
| 通用（Android 6+） | 电池优化白名单：`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 引导加入 |

- App 内做**检测 + 引导页**：无法可靠读白名单状态，所以策略是"开始拜年前展示一次图文说明"，并给"我已完成设置"确认按钮；
- 不引导也不违法，但**不做引导的后果就是被省电策略杀**——这是国产 ROM 上 90% 的"后台被杀"投诉根源。

## 4. 第四层防线：检查点续录（前功尽弃的对立面）

即使三层防线全被击穿（被强杀、系统重启、没电），**记录永远不丢**：

- **落盘时机**：每 10 秒 + 每次按键（开始/暂停/继续/撤销/结束）；
- **原子写**：`checkpoint.json.tmp` 写入 → fsync → `rename` 覆盖 `checkpoint.json`（对照网页版 db.ts 教训：绝不直接覆写）；
- **恢复**：启动发现未完成检查点 → 弹"检测到未完成的拜年记录——继续 / 放弃"→ 恢复会话 + 撤销历史 + 段计数；
- **验收**：录制中 `adb shell am force-stop` 杀进程 → 重开 → 继续记录 → 数据完整（SPEC §6 真机验收第 3 条）。

## 5. 锁屏持续定位的细节

- 前台服务持有时，**定位回调本身会保持 CPU 唤醒**，一般不需要额外 WakeLock；若发现定时器漂移（国产 ROM 深睡），加 `PARTIAL_WAKE_LOCK`（用 `setReferenceCounted(false)`，服务结束必释放）；
- 屏幕常亮（Wake Lock API 网页版那套）在安卓版**不再需要**——锁屏记录正是本版目标；
- 定位参数（高德）：连续定位模式，间隔 1s，GPS 优先；**进屋丢星与"暂停"天然兼容**（沿用 D4 结论）；
- 省电 vs 精度：1s 间隔 + 前台服务 ≈ 网页版耗电水平，2 小时约 15~25%，带充电宝无忧。

## 6. 与网页版的差异对照（提醒移植时别照搬）

| 网页版 | 安卓版 |
|---|---|
| 浏览器 Geolocation（锁屏冻结） | 高德连续定位（锁屏持续） |
| 靠"保持亮屏"防止挂起 | 前台服务 + START_STICKY + 白名单 |
| 错误静默 → 已改为可见提示 | 同样要求：权限拒绝/超时/室内 都有明确文案 |
| IndexedDB 检查点 | JSON 文件检查点（格式一致，见数据格式文档） |

## 7. 防杀专项测试方法（真机）

1. 锁屏 10 分钟走一段 → 解锁看轨迹连续；
2. `adb shell am force-stop` → 自动重启或手动重开 → 检查点续录；
3. 各 ROM 白名单引导页图文核对（借用户/朋友的真机逐台过）；
4. 长时（2h+）压力：内存观察、通知常驻、轨迹点数量与时间戳单调性。
