# Android 迁移 · 数据格式契约（v1）

> 目的：安卓版与网页版**使用同一份 JSON 数据**，导出/导入双向互通。
> 本文件是所有持久化格式的唯一权威定义——两边实现都以它为基准，格式变更必须先改本文件并同步两侧 + 补互通测试。

## 1. 全量导出文件（网页版"导出数据"按钮产物 = 安卓版导入格式）

```json
{
  "app": "baibai",
  "version": 1,
  "exportedAt": "2026-08-13T15:00:00.000Z",
  "sessions": [ /* SessionData 数组，见 §2 */ ],
  "plans": [ /* Plan 数组（今年清单），见 §6；旧版导出可能无此字段 */ ]
}
```

- `version`：导出格式版本。**解析规则：version 不符就拒绝并提示升级，不做猜测**（两侧导入均已实现：app 必须为 `"baibai"`、version 必须为 `1`，否则报中文错误）；
- `app`：必须为 `"baibai"`，否则拒绝（防止误导入其他应用的 JSON）；
- 未知字段：解析方**必须忽略**（向前兼容）；
- **null 可省略**：契约中标为 null 的可选字段（如 `leaveT`、`pos`、`lowAcc`、`jump`）在序列化时允许整体省略，解析方一律视为 `null`（安卓 `explicitNulls=false` 即按此输出，网页端解析同等对待）；
- **会话 id 安全约束**：导入时 `id` 必须匹配 `^[A-Za-z0-9_-]+$`，否则整体拒绝（防路径穿越，两端一致）。

## 2. SessionData（一场拜年）

| 字段 | 类型 | 单位/说明 |
|---|---|---|
| `id` | string | 会话唯一 id（网页版为 `s_<ts36>_<seq>`；安卓版可自定格式，只需唯一） |
| `year` | number | 拜年年份 |
| `date` | string | `YYYY-MM-DD` |
| `home` | `{lat:number, lng:number}` | 度（WGS84） |
| `nodes` | HouseNode[] | 不含 Home，见 §3 |
| `visits` | Visit[] | 按到访时间升序，见 §4 |
| `points` | TrackPoint[] | 按时间升序，见 §5 |
| `state` | `"IDLE"\|"WALKING"\|"PAUSED"\|"FINISHED"` | 会话状态 |
| `currentMode` | `"walk"\|"bike"` | 当前出行方式 |
| `finished` | boolean | 是否已结束 |
| `createdAt` / `updatedAt` | number | Unix 毫秒时间戳 |

## 3. HouseNode（一户人家）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 节点唯一 id（`n_…`） |
| `name` | string | 户名，可为空串 |
| `autoNo` | number | 自动编号（1 起，按首次到访顺序，不含 Home） |
| `pos` | `{lat,lng}` | 度 |
| `lowAcc` | boolean \| 缺省 | 坐标来自低精度 fix（可选字段） |

## 4. Visit（一次到访）

| 字段 | 类型 | 说明 |
|---|---|---|
| `nodeId` | string | `"home"` 或节点 id |
| `arriveT` / `leaveT` | number | Unix 毫秒；`leaveT` 未离开时为 null |
| `mode` | `"walk"\|"bike"` | 进入该户的出行方式 |

## 5. TrackPoint（轨迹点）

| 字段 | 类型 | 说明 |
|---|---|---|
| `t` | number | Unix 毫秒 |
| `pos` | `{lat,lng}` | 度 |
| `acc` | number | 定位精度（米） |
| `seg` | string | 段 id（`seg<n>`） |
| `jump` | boolean \| 缺省 | 疑似跳变点 |

## 6. Plan（今年清单，DB v2）

```json
{
  "year": 2027,
  "createdAt": 0,
  "updatedAt": 0,
  "items": [ { "name": "大伯家", "pos": {"lat":36.75,"lng":118.96} } ]
}
```

- `pos` 为 **null** = 手动添加、无坐标（不参与自动匹配，仅在漏访区提醒）。

## 7. 检查点（ActiveCheckpoint，崩溃恢复用）

```json
{
  "session": { /* SessionData */ },
  "actions": [ /* 撤销历史，见 §8 */ ],
  "segCounter": 3
}
```

- 保存时机：每 10s + 每次按键；**原子写**（写临时文件 → rename 覆盖）；
- 恢复语义：会话/撤销历史/段计数全部还原，可从最后动作继续撤销。

## 8. Action（撤销历史元素，LIFO）

```ts
type Action =
  | { type: 'start' }
  | { type: 'pause'; nodeId: string; created: boolean; mode: 'walk' | 'bike' }
  | { type: 'resume' }
  | { type: 'finish'; prev: 'IDLE' | 'WALKING' | 'PAUSED' | 'FINISHED' };
```

- LIFO 不变量：撤销顺序 = actions 逆序弹出；`pause` 的撤销只影响"最后那次访问"。

## 9. 关键业务常量（两侧必须一致，硬编码禁止漂移）

| 常量 | 值 |
|---|---|
| 节点合并阈值 | **10 m** |
| 高精度 fix 门槛 | ≤ **50 m** |
| 跳变判定 | <2s 内位移 > **100 m** |
| 未知距离边估算 | 直线 × **1.3** |
| 步行/骑行速度 | **1.35 / 4.0 m/s**（4.86 / 14.4 km/h） |
| 滑动平均窗口 | 5 点 |
| Douglas-Peucker 抽稀 | eps = **2 m** |
| TSP 精确解上限 | n ≤ **16**（超过走贪心+2-opt） |
| 检查点间隔 | **10 s** |

## 10. 互通验收用例（两侧都必须过）

1. 网页版导出 → 安卓导入 → 历史列表/回放/三线优化结果与网页版**完全一致**（数值逐位对照）；
2. 安卓导出 → 网页版导入 → 同上；
3. 未完成检查点：安卓录制中途强杀 → 安卓重启续录成功；该检查点文件导出后网页版也能识别其结构（至少不崩溃、给出可读提示）；
4. 版本字段不符 → 明确报错提示，不静默失败。
