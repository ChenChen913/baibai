# Android 迁移 · 开发环境与流程（v1）

> 目的：**本地零 Android 工具链**（不装 IDE、不装 SDK、不装模拟器）的前提下完成安卓版开发、测试与交付。
> 背景：本机磁盘仅约 27GB 可用、Java 仅 11（不满足安卓构建要求）、无 adb。所有重工具全部放到 **GitHub Actions 云端**。

## 1. 开发环境（本地 vs 云端分工）

| 环节 | 位置 | 本地代价 |
|---|---|---|
| 编写代码 | 本地工作区（纯文本，`android/` 目录） | 0 |
| 构建 APK | **GitHub Actions 云端**（JDK 17 + Android SDK，跑完即弃） | 0 |
| 测试 | 云端（JUnit / Robolectric，见 §3） | 0 |
| 获取 APK | `gh run download` 拉取构建产物 | 仅 APK 文件本身（约 20~40 MB） |
| 安装到手机 | APK 传给手机（数据线/微信/网盘）→ 允许"未知来源"→ 安装 | 0 |
| 本地必备 | 已有：git + gh（已登录） + 网络（仓库已配代理） | 0 |

**本地永远不安装**：Android Studio、Android SDK、模拟器、Gradle/JDK（云端负责）。唯一可选小工具是 adb（约 15MB），仅当想用数据线直接装 APK 时再说——不是必需。

## 2. CI 设计（两条工作流，路径过滤互不干扰）

- **网页版工作流**（现有 `pages.yml`）：只改网页文件才触发；
- **安卓版工作流**（新增 `.github/workflows/android.yml`）：仅 `android/**` 变更触发：

```yaml
on:
  push:
    paths: ['android/**', '.github/workflows/android.yml']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4        # JDK 17（云端，与本地无关）
        with: { distribution: temurin, java-version: '17' }
      - uses: android-actions/setup-android@v3   # 云端安装 Android SDK
      - run: cd android && ./gradlew test         # JUnit + Robolectric（纯 JVM，无需模拟器）
      - run: cd android && ./gradlew assembleDebug
      - uses: actions/upload-artifact@v4   # 上传 APK 产物
        with: { name: baibai-debug-apk, path: android/app/build/outputs/apk/debug/*.apk }
```

**开发闭环（每次迭代）**：写代码 → `git push` → 云端 5~8 分钟（构建+测试）→ `gh run download` 拿 APK → 装真机验收。代价是反馈比本地慢，换来本地零负担。

## 3. 测试策略（不装模拟器也能测）

| 层 | 手段 | 说明 |
|---|---|---|
| 算法层（主力） | **JUnit**（纯 JVM） | 把网页版 111 项测试**逐条直译**成 Kotlin 测试；数值结果与网页版逐位对照——这是移植正确性的"标准答案" |
| 框架层 | **Robolectric**（JVM 模拟安卓框架） | 服务生命周期、检查点读写、权限流程、状态机并发（对照网页版 `_infer_lock` 教训） |
| UI 冒烟 | Compose UI Test + Robolectric | 按钮可点/回调触发/禁用状态（对照 jsdom 冒烟测试） |
| 可选兜底 | GitHub Actions 云端模拟器 | 需要时再开（慢，仅疑难问题用） |
| **真机验收（必须）** | 你的手机 | 锁屏 10 分钟轨迹连续、`adb/强杀`后检查点续录、白名单引导、高德地图实显、数据互通（详见 SPEC §6 清单）——**真机是模拟器永远替代不了的** |

## 4. 软件工程流程（本次开发固定采用）

**每里程碑一个五步循环，步与步之间有可见产物：**

```
① 规格要点   ← 从 android/SPEC.md 摘本章节，补关键细节（含 Kotlin 侧决策）
     ↓
② 测试先行   ← 先把网页版对应测试直译成 Kotlin（红）——"测试即契约"
     ↓
③ 实现       ← 逐函数直译 TS → Kotlin 使测试变绿（语义等价，不重写逻辑）
     ↓
④ CI 门禁    ← push → 云端全量测试 + 构建 APK；不绿不交付
     ↓
⑤ 验收与记录 ← 真机按清单验收；更新 SPEC/changelog/契约；语义化提交
```

**三条铁律：**
1. **测试即契约**：任何模块都是"先有对照测试、后有实现"，网页版 111 项测试是唯一权威基准；
2. **文档即锚**：实现与 `android/SPEC.md`、`android/数据格式.md` 冲突时，先改文档再改代码；数据格式变更必须网页/安卓两侧同步 + 互通测试；
3. **里程碑门禁**：A-M1~A-M5 每个里程碑结束必须过：全量测试绿 + 真机验收清单 + 文档更新，三者缺一不进入下一里程碑。
